# Архитектура

```
src/expsched/
├── domain/       модели (Task, Worker, Event, Problem), ресурсы, статусы, граф, снимок для политик
├── contract/     вход и выход на Pydantic, JSON Schema, лимиты, канонический хеш, вмешательства what-if
├── analysis/     ранние и поздние сроки, ранги, нижние границы makespan
├── estimate/     оценки работы задач без длительности: логнормальное, законы ускорения, история
├── validation/   диагностики входа и карантин для режима lenient
├── engine/       дискретно-событийный симулятор, журнал, внешний исполнитель для прогона на агентах
├── policies/     fifo, priority, backfill, heft/peft, las, cpsat, реестр политик
├── verify/       попытки из журнала и проверка расписания
├── metrics/      метрики по журналу
├── explain/      по журналу: интервалы ожидания, критическая цепочка, простой узлов
├── pipeline.py   прогон целиком: вход → результат
├── emulate/      прогон на агентах: реестр агентов, драйвер (решения → команды, события → факты), shadow,
│                 replay, хаос
├── api/          REST API (FastAPI): хранилище прогонов, рабочие процессы, прогоны на агентах, локальные
│                 агенты, история оценок
└── agent/        агент: команды планировщика → контейнеры, их состояние → события; знает только contract
ui/web/           интерфейс: JS-клиент REST API (React, TypeScript, Vite)
ui/design/        макет, токены и анимации интерфейса
scenarios/        примеры входа, на них же — тесты с ожидаемыми числами
schemas/          JSON Schema входа, результата и записи журнала, генерируются из contract/
```

## Слои

Пакет импортирует только пакеты нижних слоёв; пакеты одного слоя друг друга не импортируют.

```
api | agent
emulate
pipeline
explain | metrics
verify
engine | policies
validation
estimate
analysis | contract
domain
```

Правила проверяет `lint-imports` (конфигурация — `.importlinter`), отдельно запрещено `verify → engine,
policies`: проверка расписания не должна разделять код и ошибки с тем, что она проверяет. Агент (`agent`)
импортирует только `contract` и `domain`: он работает на другой машине и знает лишь протокол.

## Принципы

- **Журнал — единственный выход движка.** Попытки, метрики, интервалы ожидания и проверка восстанавливаются
  из журнала и входа. Новый показатель — это функция журнала, а не ещё одно поле состояния движка.
- **Политика — чистая функция снимка.** `decide(Snapshot) -> list[Decision]`, без доступа к движку
  и без собственного изменяемого состояния. Снимок отдаёт read-only представления состояния без копирования.
  Решения проверяет движок.
- **Детерминизм.** Порядок событий задан ключом (время, класс события, номер); все обходы словарей и множеств,
  влияющие на решения, идут по отсортированным ключам. Хеши считаются по каноническому JSON без float.
- **Ошибки входа — данные.** Валидация возвращает список диагностик, исключения — только для нарушений
  на границе (слишком большой вход) и для ошибок программы.
- **Клиенты работают через API.** UI не импортирует `expsched`; общий контракт — JSON Schema и формат
  ответа API.

## Куда добавлять

| Что | Где |
|---|---|
| новая политика | `policies/<name>.py`, регистрация в `policies/registry.py`, тесты в `tests/unit/test_<name>.py` |
| новое поле входа | `contract/io_models.py`, доменная модель в `domain/models.py`, затем `make schema` |
| новое поле результата или записи журнала | модель в `contract/output_models.py`, затем `make schema`; без неё тесты контракта упадут |
| новый код диагностики | `validation/diagnostics.py` и проверка в соответствующем модуле `validation/` |
| новая запись журнала | `engine/simulator.py`; если её читают `verify` или `metrics` — разбор в `verify/attempts.py` |
| новая метрика | `metrics/metrics.py` |
| новая среда агента | класс с методами `Runtime` (`agent/runtime.py`), выбор в `agent/__main__.py` |
| новое действие над идущим прогоном | модель в `api/models.py` (`Action`), метод драйвера в `emulate/driver.py` |

## Прогон на агентах

Движок тот же, что в симуляции, но с внешним исполнителем: окончание и сбой попытки — факты, которые
приносят события агентов. Драйвер (`emulate/driver.py`) на каждом тике (раз в 0,1 с) переводит часы модели,
вносит отказы и возвраты агентов, сбои хаоса и уточнения оценок, отдаёт команды по решениям политики. Тики,
события агентов и действия пользователя идут в цикле событий сервера; подготовка прогона и итог (проверка,
метрики, объяснения — секунды на большом входе) — в потоке. Факты попадают в журнал, поэтому replay
воспроизводит прогон без агентов.
