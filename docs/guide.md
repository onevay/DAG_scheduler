# Руководство

Как пользоваться expsched: от примера в интерфейсе до прогона на настоящих контейнерах. Формат входа —
[input.md](input.md), политики — [scheduling.md](scheduling.md), модель длительности — [model.md](model.md),
агент — [agent.md](agent.md).

## Симуляция

1. `make run` → http://127.0.0.1:8000.
2. «Обзор» → выберите пример (например, `ml_hetero`) — он откроется в «Сборке». Или соберите DAG сами:
   задачи из палитры, связи — от правой точки задачи к левой точке зависимой.
3. Справа — свойства задачи: тип, длительность (известна или неизвестна — тогда оценка), закон ускорения,
   ресурсы, приоритет, ретраи, чекпоинты, дедлайн. Проверка идёт по ходу ввода: ошибки подсвечены на графе.
4. «Кластер» — узлы: ресурсы, скорость, метки, интервалы недоступности.
5. «Запустить» — прогон политики из панели «Политика». На странице прогона — метрики, диаграмма Ганта с
   проигрыванием, задачи и их ожидания, перепланирования; «Почему N, а не M?» — объяснения; «Сравнить
   политики» — все политики на этом входе и what-if.

Симуляция мгновенна и детерминирована: тот же вход — тот же журнал. Задачи без длительности в ней не
планируются (их работу узнают только на агентах).

## Прогон на агентах

Агент — процесс на машине с контейнерами: забирает у сервера команды «запусти попытку», запускает
контейнер, сообщает о чекпоинтах и окончании. Время модели идёт в масштабе: «100 мс» — единица времени
модели длится 100 мс стены.

### На этой машине, одной кнопкой

1. `make run` (без каких-либо переменных).
2. «Контейнеры» → «Запустить демо». Сервер запустит двух агентов fake (без контейнеров), загрузит пример
   `chaos_demo` и прогонит его в режиме shadow; через 15 секунд — итог, лента сбоев и план рядом с фактом.

Своих агентов на этой машине запускает форма «Запустить агента на этой машине» там же: id, среда (Docker,
Podman или «Без контейнеров») и ёмкость. Затем — режим «Эмуляция» или «Shadow», масштаб времени, агент для
каждого узла и «Запустить на агентах».

Токен агентов здесь не нужен: если `EXPSCHED_AGENT_TOKEN` не задан, сервер при запуске придумывает свой и
передаёт его только агентам, которых запускает сам. Управлять ими можно только с самой машины сервера.

Для Docker и Podman нужен образ встроенной нагрузки: `make workload-image` (или его образ из выпуска, см.
ниже). Без него проверка агента откажет и покажет, чего не хватает.

### На других машинах

Агентам на других машинах нужен общий с сервером токен и сетевой адрес сервера:

```bash
# сервер: слушает сеть, токен — любая длинная случайная строка
EXPSCHED_AGENT_TOKEN=… uv run --extra api uvicorn expsched.api.app:app --host 0.0.0.0 --port 8000
```

```bash
# машина с GPU: пакет из выпуска, образ нагрузки из GHCR, настройки и служба systemd
EXPSCHED_AGENT_TOKEN=… sudo -E bash install-agent.sh --repo <владелец>/expsched --id gpu-box \
    --scheduler http://<адрес сервера>:8000 --service
```

Без `--service` скрипт ставит агента в домашний каталог и печатает команду запуска; `--runtime fake` — без
контейнеров, `--dry-run` — только показать шаги. Вручную, из репозитория:

```bash
EXPSCHED_AGENT_TOKEN=… uv run python -m expsched.agent --scheduler http://<сервер>:8000 --id gpu-box
```

Агент виден на «Контейнерах» в списке «Агенты»; узлам кластера назначается его id (поле `agent`). Ёмкость
узлов одного агента вместе не больше той, что он отдаёт. Сервер без авторизации — только для доверенной
сети: открывая его наружу, закройте порт или поставьте перед ним прокси с авторизацией. Отдельный адрес только
для агентов — `EXPSCHED_AGENT_LISTEN` ([api.md](api.md)).

### Режимы

- **Эмуляция** — каждая попытка — настоящий контейнер; политика та же, что в симуляции.
- **Shadow** — то же, а рядом считается план: по каждой задаче видно, где факт разошёлся с планом и почему.
- **Replay** — «Проиграть журнал» на странице прогона: решения политики на тех же фактах, без контейнеров.

### Сбои

- «Убить контейнер» у выбранной попытки — сбой, как настоящий: попытка тратит ретрай и повторяется с
  последнего чекпоинта. «Уронить узел» — отказ узла до «Вернуть узел».
- `chaos` во входе — сбои сами собой по seed: `{"crash_every": 15, "node_down_every": 40, "node_down_for": 6,
  "seed": 1}`. Если хаос может исчерпать ретраи задачи, проверка предупредит (W080).
- Итог — секция «Сбои»: по видам, сколько задач восстановлено, сколько работы сохранили чекпоинты и сколько
  потеряно, лента «убита → повтор с позиции S».

### Неизвестные длительности

Задаче без длительности нужна оценка — медиана работы и разброс, — или её возьмут из истории прогонов этой
задачи на агентах, у задач того же типа или по умолчанию для типа. До запуска «Сборка» показывает, какой
будет оценка и откуда. По ходу прогона оценка уточняется по прогрессу задачи; после — «Оценка против факта»
на странице прогона, а наблюдённая работа пополняет историю (`runs/.estimates.json`).

## Из Python и через API

```python
from pathlib import Path

from expsched.contract.io_models import PolicyIn, load
from expsched.pipeline import run

out = run(load(Path("scenarios/ml_hetero.json").read_bytes()), PolicyIn(name="heft"))
print(out.result["metrics"]["makespan"])
```

REST API — [api.md](api.md); всё, что делает интерфейс, доступно и так.
