# Веб-интерфейс

Клиент [REST API](../../docs/api.md) на React, TypeScript и Vite. Вид — по макету из [`../design/`](../design/README.md):
цвета, шрифты, радиусы и анимации берутся из `tokens.css` и `motion.css`, стили компонентов — CSS Modules рядом с
компонентом.

Нужен Node.js 20 или новее. Команды — из корня репозитория:

```bash
make web-install   # зависимости по package-lock.json
make api           # API на http://127.0.0.1:8000, в соседнем терминале
make web-dev       # интерфейс на http://127.0.0.1:5173; запросы /v1 уходят на API
make web-lint      # ESLint, Prettier, tsc
make web-test      # Vitest
make web-build     # сборка в ui/web/dist
make web-e2e       # Playwright в Chromium: путь пример → сборка → прогон → объяснения → сравнение → what-if
```

Типы API генерируются из `schemas/openapi.json`: после изменения моделей API — `make schema`, затем
`npm --prefix ui/web run gen:types` (генерация и Prettier — файл всегда один и тот же); CI проверяет, что `src/api/schema.ts` совпадает со схемой. Запросы идут на тот
же адрес, что у страницы; другой API можно указать в `VITE_API_URL`.

```
src/
├── main.tsx       точка входа: токены, анимации, общие стили
├── App.tsx        оболочка: колонка разделов и маршруты экранов
├── api/           клиент API: schema.ts (генерируется), types.ts (короткие имена), client.ts (запросы, ApiError),
│                  hooks.ts (запросы через TanStack Query)
├── builder/       сборка: граф задач на React Flow, раскладка по слоям, свойства задачи, проверка, политика
├── cluster/       кластер: карточки узлов, шкала и список событий, интервалы недоступности
├── compare/       сравнение политик (капсулы, профиль-«цветок») и what-if (вмешательства, карточки с дельтами)
├── draft/         черновик входа: редьюсер правок problem.json, localStorage, файлы, проверка с задержкой
├── explain/       объяснения: разложение makespan на «чертеже», шаги цепочки, простой по узлам и часам
├── overview/      обзор: загрузка узлов и матрица по часам, новый сценарий из примера
├── pages/         экраны разделов; /system — живая дизайн-система со всеми компонентами
├── run/           прогон: Гант во времени, проигрывание, лента журнала, задача; расчёты полос, отказов, резервов, таблиц
├── shell/         колонка разделов, иконки, список разделов
├── ui/            общие компоненты: controls (кнопки, чипы, сегменты, переключатель, шаги),
│                  data (секция, метрика, шкала, статус, тип задачи, лента), PageHeader,
│                  plural (число со словом в нужной форме)
└── test/setup.ts  настройка тестов (jest-dom)
```

Тексты интерфейса — на русском, прямо в компонентах. Новый компонент сначала появляется на `/system` во всех
состояниях; цвета и размеры — только из `tokens.css`.

## Сквозные проверки

Playwright проходит путь пользователя в Chromium: пример → сборка → прогон → объяснения → сравнение → what-if, а
также обзор, кластер, дизайн-систему и контейнеры. Каждый экран проверяется axe (WCAG 2.1 A/AA) и на отсутствие
горизонтальной прокрутки — на ширинах 1440 и 390.

Нужны `uv`, Node.js 20 и зависимости клиента. Команды — из корня репозитория:

```bash
uv sync --extra api   # API для проверок: fastapi и uvicorn
make web-install      # зависимости клиента
make web-e2e          # при первом запуске сам скачает Chromium (~150 МБ), затем ~1 мин проверок
```

Свой API и свой клиент проверки поднимают сами: API — на :8010 с пустым временным каталогом прогонов, клиент —
сборкой через `vite preview` на :4173. Запущенные `make api` и `make web-dev` не мешают и не используются; порты
8010 и 4173 должны быть свободны.

Полезное (из `ui/web`):

```bash
npx playwright test --project=desktop   # только ширина 1440 (или phone — 390)
npx playwright test --headed            # с видимым окном браузера
npx playwright test --ui                # пошагово, с отладчиком
npx playwright show-report              # отчёт последнего запуска
```

При падении в `ui/web/test-results` лежат снимок страницы и трассировка: `npx playwright show-trace <файл>`.
